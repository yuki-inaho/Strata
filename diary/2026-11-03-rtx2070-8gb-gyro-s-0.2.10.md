# 作業記録: Strata 0.2.10 を 8GB カード + 24.5GB RAM で試す (2026-11-03)

> 個人情報・ローカルパスを除去して diary/ に収録 (2026-11-03)。
> 対象はリリース 0.2.10 のうたい文句「Qwen3.8-Flash-Next が 8GB カードで 20+ tok/s」「並列性の大幅改善」。
> この機体で実際に起動・計測し、どこまで再現できるかを確かめた記録。数値はすべてこの機体の実測。

## 環境

| 項目 | 値 |
| --- | --- |
| 本体 | 小型デスクトップ / Intel Core i7-9750H (6C/12T) |
| GPU | NVIDIA GeForce RTX 2070 8GB (sm_75, Turing) / driver 580.178.04 |
| RAM | 24.5 GB (実測 MemAvailable 12〜14GB) / swap 71GB |
| ディスク | NVMe 3.7TB (空き 617GB)、エンジン計測で 2.50 GB/s |
| PCIe | host→device 12.2 GB/s (エンジンのプローブ値) |
| OS | Ubuntu Linux 6.8.0-147 (x86_64) |
| Strata | Terminal 0.2.10 (Control 0.1.56) + engine 0.1.56 linux-x86_64-cuda-cuda13 |

`strata doctor` は ok。エンジンは署名付きフィードから 668MB を取得して自動導入された（sm_75 用の CUDA 13 パッケージ）。

## モデル選定（プランが実際に弾いたもの）

8GB VRAM + 24.5GB RAM では IQ3_S (84GB) / IQ2_XS (68GB) / Q2_0 (66GB) はプランが
「does not fit this computer」と警告する。警告なしで通ったのは Qwen3.8-Flash-Next 系で最小の
**Gyro-S (TQ1_0, 58.5GB ダウンロード / 実メモリ 27.6GB)** だけだった。ここでは Gyro-S を採用。

```
strata launch --plan --model gyro-s --family gyro --context 128k
  model     Qwen3.8-Flash-Next (Gyro) Gyro-S, 58 GB
  context   128K    pictures on (the reader runs on the processor)    parallel fit to your card
  drafting  DFlash2 (its drafter is downloaded first)
```

## 実行

```sh
sh install.sh                                     # Terminal 0.2.10 (95MB)
strata launch --model gyro-s --family gyro --context 128k --vision cpu \
  --drafting auto --tune skip --yes --no-tui
```

- ダウンロード: 59.4GB（モデル 58.5 + 画像リーダー 0.9 + DFlash2 1.2）を約 30 分（35〜43MB/s）。
- 初回のパック作成（experts を 1 ファイルに、26GB）と DFlash2 の変換が追加で数分。
- `Loading the model… 15 s` で起動。**この軽さは page cache と mmap によるもので、重みが常駐したわけではない**。

## 0.2.10 の低メモリ経路（engine log の実測行）

要求どおり context は 131072 のまま。縮めずに、下の段で逃がしている。

- `KV streaming: 20480 of 131072 cells per QSA layer in VRAM, the K/V in 1.55 GiB of pinned RAM`
  → KV ウィンドウを 20,480 に落とし、残りは pinned RAM に置いてストリーム。context は 131072 のまま。
- `expert cache auto: ... -> 445 slots`, `expert cache 445 slots, 0.43 GiB of VRAM`
  → 24,576 ランク中 445（1.8%）だけが VRAM 常駐。残りは SSD から都度読む。
- `short of GPU memory: ... the loan keeps 16, prompts are read in smaller chunks`
  → プロンプト経路の借りスロットを 16 に縮小、256 トークン刻みで読む。
- `prefill plan: ... file set 24.3 GiB does not fit the page cache 9.9 GiB -> about 3346.6 GB read from the drive per 32768-token prompt`
  → 32K プロンプト 1 本で 3.3TB 読む計算。RAM が足りない機体の本質的な限界がここに出ている。
- `WARNING: only 504 MiB of VRAM free ... (#2065)` → `--vram-reserve-mib 704` を推奨、とエンジン自身が言う。
- `--draft dflash2: on a 12 GB NVIDIA card the MTP drafter was faster ...; continuing as asked`
  → 8GB/sm_75 では未計測（コード上 "untested"）だが、Auto のまま DFlash2 をロードした（625 MiB、selector は Q4_0）。
- `no MTP layer is loaded` / `Strata set this model to one request at a time`
  → 0.2.10 の「1 ドラフター・DFlash2 は 1 リクエスト」がそのまま効いている。

## 計測（エンジン自身のログ値）

| 項目 | 結果 |
| --- | --- |
| 60 トークン（暖機後、55 再利用） | 54 生成 / 5.76s = **9.4 tok/s**、DFlash2 28/36 採用 |
| 1,653 トークンのプロンプト | 36.2s で読込（45.7 tok/s）、生成 8.2 tok/s、この 1 本で SSD から 25.1GB 読込 |
| 17,948 トークン（opencode 初回） | 481s で読込（37.3 tok/s）、生成 10.5 tok/s |
| 18,095 トークン（2 ターン目） | 18,050 再利用 → 45 だけ読んで 3.4s、生成 11.8 tok/s |
| 画像（CPU リーダー、896x448） | 15.9s で「4217: red, blue」（正解） |
| 同時 2 リクエスト（slot=1） | 8.6s / 13.0s に完了＝直列化。取りこぼしなし |
| セッション累計の SSD 読込 | 1.55TB（起動から十数リクエスト時点） |

ウォーム時の decode は **9〜12 tok/s**、prefill は **37〜46 tok/s**。同じ機体で 20 tok/s は出ない。

## opencode 連携

- `strata connect opencode --check`（0.2.10 の自己チェック）: prompt 7.1s で "pong"、tool call 21.9s で
  `get_weather {"city":"Paris"}` → **両方 ok**。
- 実機の OpenCode は **v2.1.3**。`strata connect opencode` が印字する設定（`npm` / `options` / `tool_call`
  の旧フィールド形）でもプロバイダは登録された（#4528 は cannot reproduce で close、整合）。
- ただし既定の `limit.output: 4096` は未解決の **#5006**（長いセッションで compaction が 4096 で切れて
  `Compaction summary reached the output token limit` になる）。#5006 の推奨どおり
  **`output: 16384` / `input: 114688` / `compaction.buffer: 24576`** に変えて使った。
- 実際の `opencode run`:

```
opencode run --model strata/qwen3.8-flash-next-gyro-gyro-s --auto \
  "Read the file notes/key.txt in this folder and reply with only the access code."
→ Read notes/key.txt → ZX-4419   (8m44s、うち初回 prefill が 481s)
```

  opencode のシステムプロンプト + ツール定義で約 7.4K トークン、実測 17,948 トークンの prefill。
  ツール呼び出し → 結果 → 回答まで通り、**opencode 連携は成立**。設定はプロジェクト単位の
  `opencode.jsonc` に置き、グローバル設定は触っていない。

## わかったこと

1. **8GB カードで 128K context は本当に起動する**（0.2.10 のメモリ段は設計どおり動く）。ただし
   この機体では「カード」ではなく **RAM 24.5GB** が律速で、expert の 98% が SSD 読みになる。
2. その結果、**decode 9〜12 tok/s / prefill 37〜46 tok/s**。20+ tok/s は RAM 64GB 級の話で、
   リリース本文の 63〜73 tok/s も「大きいカードを手で 8GB に絞った、RAM に余裕のある検証機」の数字。
   実 8GB カード（A750）の 12.7〜14.8 tok/s に近い側だと確認できた。
3. 長いプロンプトは I/O で決まる。1.6K トークンで 25GB、32K で 3.3TB の読み込み予測。
   エージェント用途は「1 ターン 8 分」級になる（実測 8m44s、うち prefill 8 分）。
4. 並列性の改善（all-cards split）は **2 枚の sm_86/sm_120 か 4 枚の R9700** が条件で、1 枚では対象外。
   代わりに 0.2.10 の「DFlash2 は 1 リクエスト」が効き、同時 2 本は直列化されるのを確認した
   （MTP にすれば複数 slot になるが、MTP 層 5.2GB の追加ダウンロードが必要なので今回は未実施）。
